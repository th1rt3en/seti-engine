# 1.0 checklist

Drawn up 2026-10-19 from `docs/PLAN.md` (phase 6, section 5 gates, section 7 risks), `docs/spec/`, `docs/asset-gaps.md` and the state of the code. The plan itself has no checklist: this file is the working list. Tick an item when it is done and checked; add a date and a note. Items marked *(proposal)* are the agent's suggestions and are not yet approved by the owner.

## A. Rules fidelity

- [ ] Every rule ID has a test (CLAUDE.md hard rule 2). `python tools/engine/rule_coverage.py` on 2026-10-19: 418 rules, 276 named in code, 248 named in tests. Work the gaps by spec file (`board-and-sectors`, `board-stars-and-planets`, `setup`, `board-solo-and-scoring`, `board-alien-species`, `solo`, `turn-structure`), or record why a rule has no test.
- [ ] A review agent has checked the rules changes of the expansion against the rulebook text (CLAUDE.md, Conventions).
- [ ] Every entry of `docs/spec/ambiguities.md` is ruled and copied into the spec. Check the table for open entries; A-001 still has an open part (what orbiting or landing on the SE EN 01 planet costs and gives).
- [ ] Owner check of the expansion data (`docs/spec/expansion-data.md`: organizations, quick start cards, the 42 main-deck cards, the three alien species), which the spec still marks "owner check pending".
- [ ] Promo card "Space Agencies" (SETI promo 03, EXP-PROMO-01, A-035) is implemented or taken out of scope by the owner.
- [ ] Rulebook worked examples are scripted scenarios; the random-play fuzzers run for 1 to 4 players with and without the expansion; replay equals live state (re-run before each release).

## B. Play-tests (the biggest open item)

- [ ] Several full games with experienced players, base game only: 2, 3 and 4 players and solo, every difficulty of the rival.
- [ ] The same with the expansion: organizations, quick start cards, signal tokens, the 4-round variant, each new species (Arkhos, Glyphids, Amoeba), solo with the expansion.
- [ ] Flows that were built but never played live (found in the last weeks): Xenolab tiles, the Exertian card flow, mission circle clicks, the Mars landing choice, the Glyphids top row, undo and take-back, the admin cancel and delete actions, Futurespan Institute, the organelle skip.
- [ ] Reconnects, a closed tab and a refresh in the middle of a decision, on desktop and on a phone.
- [ ] Every bug found is fixed with a test, or recorded.

## C. Backend, rating and accounts

- [ ] Rating: pairwise Elo as in section 6 and D37 (start 0, K 60/40/20, floor 100) is checked against a few played games; admin cancel never changes a rating.
- [ ] Rating integrity: collusion heuristics (the plan's risk table; D24 removed the minimum game length). Decide what to flag, and who looks at it.
- [ ] Abuse controls: rate limits on signup, login, guest play and game creation (one exists for creating a game), Turnstile tested in a real browser (never done, `docs/deployment-status.md`).
- [ ] Password reset: D29 chose none. Decide: keep none and say so on the signup page, or add one.
- [ ] Timers: real-time and turn-based clocks, timeouts, kicks and abandoned games checked on live games (D24 to D28, D34).
- [ ] The archive (D25) is checked on a finished game, a resigned game and a cancelled one, and a replay is built from each.
- [ ] Typed action union in the protocol (actions are generic objects today).
- [ ] D1: backups or an export plan; the migrations of production match the repository (0003 and later).

## D. Operations

- [ ] Load test: many simultaneous games through the Worker, Durable Objects and the engine on Cloud Run. Set `--max-instances` and concurrency from the result (`docs/deploy-engine.md`).
- [ ] Cloud Run min instances = 1 at launch (cold starts, plan section 7).
- [ ] Observability: errors from the engine, Worker and website are collected somewhere the owner looks; an alert for a failing archive and for engine errors.
- [ ] A runbook for the owner: deploy order (engine, Worker, website), rollback, rotating the signing keys, the admin passphrase, taking the site down on CGE's request.
- [ ] `docs/deployment-status.md` is brought up to date (it dates from 2026-10-14) and the D15 row of the plan is brought in line with D37.
- [ ] CI is green on main: Python tests, ruff, mypy; TypeScript tests, typecheck and lint (a few existing lint findings remain in `GameClient.tsx`).

## E. Legal and assets

- [ ] The source and permission of the Steam Workshop assets are recorded (`LEGAL.md`, `docs/asset-gaps.md` licensing).
- [ ] The footer carries the fan-project disclaimer and the takedown contact; nothing suggests CGE's endorsement.
- [ ] Every imported asset is in the provenance manifest (`packages/assets/PROVENANCE*.md`).
- [ ] Replace the placeholders that show: the Glyphids board and translation board (generator watermark), the drawn card icons, the low-resolution data and analyze icons, the Anomaly token (hexagon until a picture is supplied if one is still missing).
- [ ] The names and the owner's `asset-gaps.md` list are reviewed once more before the launch gate; items the owner cannot supply are accepted in writing.

## F. UI improvements

Mark each as *wanted* or *not wanted* and the agent works from the wanted ones.

### F1. Known gaps (from `PROGRESS.md` and the work so far)
- [ ] The Mascamite sample spaces have no place on the species board yet (they are buttons); put them on the board like the other trace spaces.
- [ ] The tiles and boards that are measured by eye (`speciesSpaces.ts`, `PlayerBoard.tsx`, the Amoeba board, the Exertian prompt circles) are re-checked on several screen sizes.
- [ ] Remaining choices that are still buttons of the bar, where a place on a picture exists: audit each decision kind against `buildSpots` (`targets.ts`).
- [ ] Every choice made by clicking has a confirm and cancel (or the setting that turns confirmations off), and the same look everywhere (one component for the buttons over a card, a tech and a board place).
- [ ] Log: every gain has its own line with its source (rival turns, anomalies, glyphs, organelles, end of game); an audit of the remaining merged lines.

### F2. Phone and tablet
- [ ] Every panel and dock is checked at 360 and 390 px wide: the player boards, the species boards, the tracker, the log, the display and the hand.
- [ ] Touch targets on the board are at least 44 px; the highlighted places do not overlap.
- [ ] Pinch zoom and pan on the board are smooth, and a double tap does not click a place by mistake.

### F3. Clarity (proposals)
- [ ] *(proposal)* A short "what can I do now" help in the context bar for each decision kind, behind the ? button.
- [ ] *(proposal)* A "last move" highlight on the board (the place or piece the opponent just changed), also on reconnect.
- [ ] *(proposal)* A turn notification: the page title and a sound when it becomes the player's turn (the sound setting exists), and an optional browser notification for turn-based games.
- [ ] *(proposal)* A filter of the log (mine, rival, gains only) and a search.
- [ ] *(proposal)* Keyboard shortcuts for the common actions (confirm, cancel, end turn, undo) and a list of them.
- [ ] *(proposal)* A first-game tutorial or guided tour for new players, and a rules summary page for each phase of a turn.
- [ ] *(proposal)* Colour-blind friendly player colours and a high-contrast mode; a check with a screen reader of the lobby, the settings and the context bar.

### F4. Site
- [ ] *(proposal)* Profile page: rating history graph, games played, win rate by player count and with or without the expansion.
- [ ] *(proposal)* Lobby: filters (speed, players, expansion, rated), a clearer rated or casual badge.
- [ ] *(proposal)* A page that shows the card list (exists) with a link from the log and the hand to each card.
- [ ] *(proposal)* Error and empty states: a game that does not exist, a full lobby, a lost connection, an engine error (what the player sees and what they can do).

## G. Launch steps

- [ ] Internal alpha: gate 4 of the plan (the owner reviews).
- [ ] Beta: friends and experienced players, rated play off or marked as a trial.
- [ ] Gate 5 of the plan: the owner opens rated play. Rated play is announced with the rules above (rating formula, timeouts, how to report a problem).
- [ ] After launch: a place for bug reports, a weekly look at the errors and archive failures, a plan for fixes to the rules (a change goes through a test per card or rule).
