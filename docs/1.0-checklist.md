# 1.0 checklist

Drawn up 2026-10-19 from `docs/PLAN.md` (phase 6, section 5 gates, section 7 risks), `docs/spec/`, `docs/asset-gaps.md` and the state of the code. The plan itself has no checklist: this file is the working list. Tick an item when it is done and checked; add a date and a note. Items marked *(proposal)* are the agent's suggestions and are not yet approved by the owner.

## A. Rules fidelity

- [ ] Every rule ID has a test (CLAUDE.md hard rule 2). `python tools/engine/rule_coverage.py` on 2026-10-19 (ranges such as "ORBIT-01 to ORBIT-04" now count): 418 rules, 326 named in code, 293 named in tests. About 125 rules have no test: roughly 45 are data, board-layout or UI descriptions that a test cannot check (needs the owner's decision, see section H), the rest are behaviours to test (sector, card-term, solo and FAQ rules). Work the list with `scratchpad/untested.py`-style output: each rule gets a test or an exemption.
- [ ] A review agent has checked the rules changes of the expansion against the rulebook text (CLAUDE.md, Conventions).
- [ ] Every entry of `docs/spec/ambiguities.md` is ruled and copied into the spec. Check the table for open entries; A-001 still has an open part (what orbiting or landing on the SE EN 01 planet costs and gives).
- [ ] Owner check of the expansion data (`docs/spec/expansion-data.md`: organizations, quick start cards, the 42 main-deck cards, the three alien species), which the spec still marks "owner check pending".
- [ ] Promo card "Space Agencies" (SETI promo 03, EXP-PROMO-01, A-035) is implemented or taken out of scope by the owner.
- [ ] Rulebook worked examples are scripted scenarios; the random-play fuzzers run for 1 to 4 players with and without the expansion; replay equals live state (re-run before each release).

## B. Play-tests (the biggest open item)

- [ ] Several full games with experienced players, base game only: 2, 3 and 4 players and solo, every difficulty of the rival.
- [ ] The same with the expansion: organizations, quick start cards, signal tokens, the 4-round variant, each new species (Arkhos, Glyphids, Amoeba), solo with the expansion.
- [ ] Flows that were built but never played live (found in the last weeks): Xenolab tiles, the Exertian card flow, mission circle clicks, the Mars landing choice, the Glyphids top row, undo and take-back, the admin cancel and delete actions, Futurespan Institute, the organelle skip.
- [ ] Reconnects, a closed tab and a refresh in the middle of a decision, on desktop and on a phone.
- [ ] Every bug found is fixed with a test, or recorded.

## C. Backend, rating and accounts

- [ ] Rating: pairwise Elo as in section 6 and D37 (start 0, K 60/40/20, floor 100) is checked against a few played games; admin cancel never changes a rating.
- [ ] Rating integrity: collusion heuristics (the plan's risk table; D24 removed the minimum game length). Decide what to flag, and who looks at it.
- [ ] Abuse controls: rate limits on signup, login, guest play and game creation (one exists for creating a game), Turnstile tested in a real browser (never done, `docs/deployment-status.md`).
- [ ] Password reset: D29 chose none. Decide: keep none and say so on the signup page, or add one.
- [ ] Timers: real-time and turn-based clocks, timeouts, kicks and abandoned games checked on live games (D24 to D28, D34).
- [ ] The archive (D25) is checked on a finished game, a resigned game and a cancelled one, and a replay is built from each.
- [ ] Typed action union in the protocol (actions are generic objects today).
- [ ] D1: backups or an export plan; the migrations of production match the repository (0003 and later).

## D. Operations

- [ ] Load test: many simultaneous games through the Worker, Durable Objects and the engine on Cloud Run. Set `--max-instances` and concurrency from the result (`docs/deploy-engine.md`).
- [ ] Cloud Run scaling: read on 2026-10-19, `seti-engine` runs with **max instances 1**, no minimum instance (it scales to zero), concurrency 40, 2 CPU, 1 GiB, startup CPU boost on. Plan section 7 wants min instances 1 at launch (cold starts), and one instance caps the number of simultaneous games. Needs the owner's decision on cost, see section H.
- [ ] Observability: errors from the engine, Worker and website are collected somewhere the owner looks; an alert for a failing archive and for engine errors.
- [ ] A runbook for the owner: deploy order (engine, Worker, website), rollback, rotating the signing keys, the admin passphrase, taking the site down on CGE's request.
- [x] `docs/deployment-status.md` is brought up to date and the D15 row of the plan is brought in line with D37 (2026-10-19).
- [x] CI is green on main: Python tests (863), ruff, mypy; TypeScript tests, typecheck and lint (the web lint findings were fixed 2026-10-19; `.open-next` build output must stay out of lint runs).

## E. Legal and assets

- [ ] The footer carries the fan-project disclaimer and the takedown contact; nothing suggests CGE's endorsement.
- [ ] Every imported asset is in the provenance manifest (`packages/assets/PROVENANCE*.md`).
- [ ] Replace the placeholders that show: the Glyphids board and translation board (generator watermark), the drawn card icons, the low-resolution data and analyze icons, the Anomaly token (hexagon until a picture is supplied if one is still missing).

## F. UI improvements

Mark each as *wanted* or *not wanted* and the agent works from the wanted ones. Items marked *(proposal)* are the agent's suggestions; the others come from gaps seen in the code and in play.

### F1. Known gaps
- [ ] The Mascamite sample spaces have no place on the species board yet (they are buttons); put them on the board like the other trace spaces.
- [ ] The places that were measured by eye (`speciesSpaces.ts`, `PlayerBoard.tsx`, the Amoeba and Arkhos boards, the Exertian prompt circles, the organelle tokens) are re-checked on several screen sizes and on a high-density screen.
- [ ] Audit every decision kind against `buildSpots` (`targets.ts`): any choice that has a place on a picture is a highlighted place, and only the rest is a button of the bar.
- [ ] One look for every confirm and cancel: the buttons over a card, a tech, a display card, the deck, a board place and an alien card are one component with one style, and the setting that turns confirmations off applies to all of them.
- [ ] Log: every gain has its own line with its source. Audit the lines that are still merged (rival turns, glyphs, organelles, the signals of a scan, the end of the round) and the lines that name a hidden card.
- [ ] The tracker, the player boards and the missions panel show the same numbers as the engine in every phase (income, tucked cards, end-of-game cards, danger, signal tokens); a test compares them for a few saved games.
- [ ] Every decision has a clear text in the context bar that names its source in parentheses (done for most; audit the rest), and says why a choice is empty (no organelle, no probe to move, no card to take) with a skip button.

### F2. Phone and tablet
- [ ] Every panel and dock is checked at 360 and 390 px wide and in landscape: the player boards, the species boards, the tracker, the log, the display, the hand and the context bar.
- [ ] Touch targets on the board are at least 44 px and the highlighted places do not overlap; a place that is hard to hit gets a larger invisible target.
- [ ] Pinch zoom and pan on the board are smooth, a double tap does not click a place, and the board keeps its zoom while the page is open.
- [ ] The page keeps its place when the phone is rotated, when the keyboard opens and when the tab goes to the background and comes back.
- [ ] The hand, the display and the log do not hide the board when open: a clear way to fold all docks at once.

### F3. Clarity and help
- [ ] *(proposal)* A short "what can I do now" help for each decision, behind the ? button of the context bar, with a link to the rule text.
- [ ] *(proposal)* A "last move" highlight on the board (the place or piece the opponent just changed), also after a reconnect or a refresh.
- [ ] *(proposal)* A "what changed since my last turn" summary when it becomes the player's turn in a turn-based game: the moves of the opponents in one list.
- [ ] *(proposal)* A preview of the result of a move before it is confirmed: the score, the resources and the tracks after it (for a launch, a landing, a research, a mission).
- [ ] *(proposal)* A rules lookup: a page and a search box with the spec text of each rule and each card effect, opened from a card, a tech or a log line.
- [ ] *(proposal)* Tooltips for the icons of the tracker, the log and the cards (what the symbol means, in words).
- [ ] *(proposal)* A first-game tutorial or guided tour for new players, and a short rules summary for each phase of a turn.
- [ ] *(proposal)* A legend of the log: the icons and the words of its lines.

### F4. Log and replay
- [ ] *(proposal)* A filter of the log (mine, the rival, the opponents, gains only, one source) and a search.
- [ ] *(proposal)* Clicking a log line shows the board as it was after that move, without leaving the live game.
- [ ] *(proposal)* The replay viewer: step forward and back, play and pause, jump to a round, see the log line of each step, and share a link to a move.
- [ ] *(proposal)* The log can be copied or downloaded as text for a bug report or a discussion.
- [ ] The log keeps its place when new lines arrive while the player has scrolled up, with a "new moves" button; the size the player set (desktop) is kept.

### F5. Turn flow and feedback
- [ ] *(proposal)* A turn notification: the page title and a sound when it becomes the player's turn (the sound setting exists), and an optional browser notification for turn-based games.
- [ ] *(proposal)* Short animations for the main events (a probe moving, a signal, a card going to the hand, a rotation), with a setting to turn them off and respect for "reduce motion".
- [ ] *(proposal)* A visible clock for each player with a warning in the last minute; a clear "waiting for [name]" state with the reason the engine waits.
- [ ] *(proposal)* Undo and the take-back of a trade (D31, D32) shown as one clear control that says what will be taken back.
- [ ] *(proposal)* Keyboard shortcuts for the common actions (confirm, cancel, end turn, undo, fold a dock) and a list of them.
- [ ] *(proposal)* A guard against a mis-click on the final steps: ending the turn with a main action left, or with a free card still to take.

### F6. Cards and boards
- [ ] *(proposal)* A larger card view (hover or long press) that shows the card text as text next to the picture, for the cards whose print is small.
- [ ] *(proposal)* Cards in the hand can be sorted and grouped (by cost, by sector colour, by type) and the order is remembered.
- [ ] *(proposal)* A tech and gold tile overview that shows who has what and what is still open, and a running estimate of the end-of-game cards and gold tiles (the player's own, labelled as an estimate).
- [ ] *(proposal)* Highlight the sectors, planets and probes that a hovered card or mission refers to.
- [ ] The player boards panel shows the other players' boards read-only and at the same size as the player's own.
- [ ] The solo rival: its board, deck and action cards are as readable as a player's.

### F7. Settings and accessibility
- [ ] *(proposal)* Colour-blind friendly player colours (shapes or patterns on the pieces) and a high-contrast mode.
- [ ] *(proposal)* A check with a screen reader of the lobby, the settings, the context bar and the log; a logical focus order and visible focus rings on every interactive element, including the places on the board.
- [ ] *(proposal)* A text size setting that applies to the whole page (the hand size setting exists); a dark and a light theme.
- [ ] *(proposal)* Settings are saved with the account, not only in the browser, and follow the player to another device.
- [ ] Respect "reduce motion" and "prefers contrast" in every animation and highlight.

### F8. Site
- [ ] *(proposal)* Profile page: rating history graph, games played, win rate by player count and with or without the expansion, and a list of past games with a link to each replay.
- [ ] *(proposal)* Lobby: filters (speed, players, expansion, rated, real-time or turn-based) and a clearer rated or casual badge.
- [ ] *(proposal)* A page of the rules of the site: the rating formula, the clock speeds, the timeout and kick rules, the fan-project notice and how to report a problem.
- [ ] *(proposal)* Leaderboard: a search for a player, a filter by number of rated games, and a note on the floor of 100.
- [ ] *(proposal)* A "play again with the same players" button at the end of a game, and an invite link that is easy to share.
- [ ] *(proposal)* A page for the end of a game: the final scores itemised (board, cards, gold tiles, Exertian, glyphs, danger loss), who won, the rating changes, and links to the replay and to a new game.
- [ ] *(proposal)* Error and empty states: a game that does not exist, a full lobby, a lost connection, an engine error, a game cancelled by the administrator (what the player sees and what they can do), and a clear message while the engine starts.
- [ ] *(proposal)* Page speed: the first load of the game page is measured on a phone, its large card pictures are loaded as needed, and the site works on a slow connection.

## G. Launch steps

- [ ] Internal alpha: gate 4 of the plan (the owner reviews).
- [ ] Beta: friends and experienced players, rated play off or marked as a trial.
- [ ] Gate 5 of the plan: the owner opens rated play. Rated play is announced with the rules above (rating formula, timeouts, how to report a problem).
- [ ] After launch: a place for bug reports, a weekly look at the errors and archive failures, a plan for fixes to the rules (a change goes through a test per card or rule).

## H. Decisions needed from the owner

These block items above. Each has the details and a recommendation.

- [ ] **Rule IDs that are data, layout or UI descriptions** (BOARD-01 to BOARD-08, BOARD-21 to BOARD-75, ALIEN-DATA-01 to 03, SOLO-DATA-01/02/11/13/20/30, SETUP-01 to 03, EXP-02, EXP-04, ALIEN-UI-01, ALIEN-MASC-06): hard rule 2 says every rule ID has a test. These rules describe pictures, counts and tables (for example "the tech board has 12 stacks"), so a behaviour test does not fit. Options: (a) write small data-integrity tests that name them (counts and tables checked against the data files); (b) mark them in the spec as "data, verified by the owner's review" and let the coverage tool skip them. Recommendation: (b) for UI and picture-only rules, (a) for the table rules (BOARD-05, BOARD-21, SOLO-DATA-11/13/20), done by the agent. Changing hard rule 2 needs the owner's approval and a decision-log entry.
- [ ] **Promo card "Space Agencies" (EXP-PROMO-01, A-035):** the owner ruled that its memory between games is left out; the card itself is not implemented. Decide: implement the card now (launch a probe and gain a signal token, and no memory), or leave it out of 1.0.
- [x] **A-001, the SE EN 01 promo planet:** settled. The owner's rulings of 2026-10-12 (orbit: 11 points, 3 publicity, 1 trace of any color; land: 11 points, 4 data, 1 yellow trace; normal costs; 1 orbiter and 1 lander space; only the card's owner), the official FAQ (it counts as a planet for missions and the gold tile) and the owner's restatement of 2026-10-19 agree, and the engine implements and tests them (`tests/test_promo.py`, PROMO-02).
- [ ] **Cloud Run scaling and cost (section D):** the engine now has max instances 1 and min instances 0. Proposed for launch: min instances 1 (no cold start; an always-on 2 CPU / 1 GiB instance has a monthly cost that depends on the region price, roughly a few tens of dollars) and max instances 5 to 10 (the engine keeps no state, so more instances are safe; the cap is the budget). Decide the two numbers and whether the agent may run `gcloud run services update seti-engine --min-instances N --max-instances M`. A load test (below) should come first to size it.
- [ ] **Load test (section D):** needs permission to create many test games against the live Worker and engine (they would be marked as test games and removed with the admin page), or a separate staging deploy. Say which, and the largest number of simultaneous games to try (proposal: 20, then 50).
- [ ] **Observability (section D):** where errors should go. Options: Cloudflare Workers Logs and Observability for the Worker and the website (built in, free tier), Google Cloud Error Reporting and Logging for the engine (already collects Cloud Run logs), plus an email or chat alert for archive failures. Say which alert channel to use (an email address or a chat webhook; do not paste a secret here, give it to the agent through a secret manager or `wrangler secret`).
- [ ] **Password reset (section C):** D29 chose accounts without email, so there is no reset. Options: (a) none, the player makes a new account (a lost password loses the rating); (b) the administrator resets a password on request (a button on `/admin`, needs no email); (c) an optional email address for a reset link (changes D29). Recommendation: (b) for 1.0.
- [ ] **Collusion and abuse rules (section C):** what the site should flag in rated games. Proposal, for review by the owner only (no automatic penalty): the same two accounts playing many rated games together in a day; a rated game that ends by resignation in the first N moves; large rating gain from a few short games. Decide the thresholds, and who looks at the flags (the `/admin` page can list them).
- [ ] **Asset permission record (section E):** `LEGAL.md` needs the source and the permission for the Steam Workshop assets (author name or workshop link, and what permission the owner has). The agent cannot find this; only the owner can write it. Also the owner's written confirmation from the GitHub repo owner (D3) should be recorded (where it is kept, not its content).
- [ ] **Clean pictures (section E):** the Glyphids board and translation board carry a generator watermark; the card icons and the data and analyze icons are drawn or low-resolution. Supply clean pictures, or accept the current ones for 1.0.
- [ ] **Expansion card check (section A):** the owner checks the organizations, quick start cards and the 42 main-deck cards against the physical cards. The agent can build a review page (as for the base cards, `tools/web/build_card_review.py`) so that the check is a list to tick; say if you want that page.
- [ ] **Play-testers (section B):** who plays, how many games, base and expansion. The agent cannot recruit; it can prepare a one-page guide for testers and a bug-report form that collects the game id.
- [ ] **UI proposals (section F):** mark each proposal as wanted or skip (the checklist page has the buttons and a "Copy my picks" button).
